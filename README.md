# 时间轴上的印度

一个可拖拽浏览的印度历史时间轴网页应用，收录从史前时代到二十一世纪的 440 个重大历史事件，支持中文和英文。

网站框架来自姊妹项目“时间轴上的中国”（plantatree2023/chinesehistory），内容、配色、字体、纹理和背景音乐换成了印度的。

在线访问：https://india.zhongshutime.com/ （计划部署在 Cloudflare，域名待配置）

## 功能

- 页面正中为时间轴，可用鼠标 / 手指左右拖拽、滚轮、方向键或底部缩略条浏览（点击缩略条后也可用方向键、Home、End）；点击左上角标题回到时间轴开头（外观与普通标题相同）；到达两端时隐藏对应的翻页按钮；最早的时期之前留有一段渐隐的轴线
- 跳转到时期：电脑上点顶栏时期名右侧的 ▾，从列表（色块、时期名、年代）中选择；手机上点底栏左侧的“■ 当前时期 ▾”，从底部弹出的色块面板中选择。选择后跳到该时期的第一个事件；Esc、点外面关闭，可用方向键和 Enter 操作
- 时期更迭事件在时间轴上用菱形标记（新时期的颜色）；时间轴到卡片的连线使用该事件所属时期的颜色
- 全屏模式（隐藏工具栏）下，每个时期开始处的左上角显示时期名，一条时期色竖线从顶部一直渐隐到轴线，标出时期的起点；名字和竖线用该时期的颜色、不透明度偏低，名字压在卡片上层但不影响点击，竖线在卡片下层、不横穿卡片；时期太短放不下名字时不显示
- 自动播放：页面加载后时间轴默认缓缓向右前进（约每 30 秒一屏）；手动浏览时暂停，停止操作约 3 秒后以原来的速度自动继续；右上角的播放按钮依次切换：播放（一倍速）→ 二倍速（双箭头图标，二倍速时按钮角上显示“2×”）→ 暂停，空格键直接播放 / 暂停；手动暂停后本次访问中不再自动继续，直到再次播放（从一倍速开始）；到达末端停止；系统设置了“减少动态效果”时不自动开始
- 背景音乐：音量较小、循环播放，页面加载后立即尝试播放；浏览器不允许操作前发声时，音乐按钮闪动几次提示（iPhone / iPad 上始终如此），访问者第一次点击、触摸或按键（任何位置）后开始；右上角的喇叭按钮可以关闭，并记住选择。每个数据集在 `music` 字段中配置自己的音乐（音频放在 `audio/`），没有配置则不显示音乐按钮
- 背景纹理：时间轴后面铺一层清淡的纹理（印度数据集为莲花纹），每个数据集在 `texture` 字段中配置自己的纹理（图片放在 `textures/`），深浅两种配色自动适配
- 事件卡片交错排列在轴线上下方，包含代表性图片与简要说明；图片大小按事件的重要程度（1–10）分三级：1–5 小、6–7 中、8–10 大（重大事件）；轴线按时期着色，背景随时期颜色渐变（保留纸色主调）
- 为保持清爽，任意一屏宽度内最多显示 6 个事件；时间轴区域宽度不小于 1600px 的大屏幕上最多 8 个，避免大屏上留白过多（窗口大小变化时自动重新排版）
- 点击事件查看详细说明（≤600 字）和最多 9 张图片，调试模式下可编辑、删除
- 底部“浏览所有历史事件”按钮打开侧栏，按时间顺序列出全部事件，支持搜索；调试模式下可编辑、删除
- 侧栏可按**重大事件**（重要程度 8–10）、**时期更迭**（这两项为勾选框，排在最前）、**事件类型**（带颜色的下拉多选，如政治、战争、文化、科技）、**时期**（带颜色的下拉多选）和**时间范围**筛选，可与搜索同时使用；可选项由数据集决定（时期来自 `eras`，类型来自 `types`，年份范围来自事件）
- 详情和侧栏列表中显示事件类型（描边的类型色标签，与时期的实心色块区分）；重要程度是内部信息，只在编辑页（调试模式）中显示和修改
- 右下角“+”按钮（悬浮在底栏上方）添加新事件（支持图片网址或本地上传，可为每张图片填写标题；调试模式下显示）
- 编辑页（调试模式；访问者的建议模式不提供）：
  - 编辑页较宽（大屏约 1080px）；悬停图片标题显示完整标题；代表图之后的图片可以拖动排序（代表图固定在第一张）；点进“粘贴图片网址”输入框时自动粘贴剪贴板中的网址
  - 点击图片缩略图放大查看、左右切换；查看器中“设为代表图”（移到第一张，仍显示这张）和“从本事件移除”（显示下一张，没有图片时关闭；图片文件不删除），都只改编辑中的内容，点“保存”后生效
  - 参考链接末尾总预留一个空行，填入（粘贴）链接后自动再预留一个（空行不保存）；每行末尾的 ↗ 在新标签页中打开；粘贴维基百科 / 百度百科链接后自动填写“维基百科 - 词条名”“百度百科 - 词条名”：先按链接中的词条名填写，再由本地服务器查询（维基百科跟随重定向、取简体标题；百度百科读取网页标题）后更新；不覆盖手动输入的标题
  - “图片”标题行右侧的“搜图”按钮用事件名称在新标签页中搜索图片，▾ 选择 Google / Bing / 百度 / Google · 维基共享资源，记住上次的选择
- 编辑页点击“保存”后按钮立即显示“保存中…”（本地文件模式下等待写入完成，失败时显示原因并可再次保存），完成后显示“✓ 已保存”再关闭
- **深色模式**：默认浅色（日间）；右上角的月亮 / 太阳按钮切换浅色与深色，记住选择（保存在当前浏览器中）
- **首次访问提示**：第一次打开时提示怎么用，只提示一次（记在当前浏览器中）。电脑上是三步指引（聚光灯依次指向时间轴、卡片、“浏览所有历史事件”按钮，可跳过，可用“上一步”或 → / ← 切换，Esc 关闭，期间自动播放停住）；手机上是底部气泡，点“知道了”或点别处收起。通过分享链接直接打开详情时不提示
- **关于本站**：电脑上右上角 ⓘ 按钮（放大缩小按钮左边）打开，介绍网站、用法、文字和图片来源与许可、字体、背景音乐（数据集 `music.title` / `music.credit`，没有时不显示）、反馈与隐私（GitHub 源代码链接只在调试模式下显示）；手机上深色模式、分享、关于本站收进右上角的“⋯”菜单
- **分享面板**：右上角“分享时间线”和详情中的分享按钮打开（标题分别为“分享时间线”“分享事件”；分享时间线用当前网址的全部参数，如数据集、位置，只去掉 `debugMode`；分享事件只带该事件），可复制链接、微信二维码、微博、QQ空间、Facebook、Twitter、LinkedIn、Telegram、邮件。手机上另有“微信好友”：在微信里打开时提示点右上角 ··· 发送给朋友或分享到朋友圈；在其他浏览器中用系统分享面板（可选微信），没有系统分享面板时复制链接并提示到微信中发送（网页不能直接调起微信的分享）
- **网址记录当前状态**，可以直接打开、刷新和分享：`?id=e052` 打开该事件的详情；`?browse` 打开侧栏，搜索词和筛选条件也写在网址中（如 `?browse&q=长城&major=1&type=war,culture&era=唐&from=-221&to=907`，类型使用 `key`）；`?at=755` 为时间轴中央的年份。打开详情、侧栏时新增一条浏览记录，浏览器的“返回”会先关闭它们；改筛选、拖动只更新当前网址。详情中有“分享链接”按钮（手机上调用系统分享，电脑上复制链接），打开详情时浏览器标题显示事件名
- **下拉刷新**：手机等触屏设备上向下拉动页面、松开即可刷新（横向拖动时间轴、侧栏或弹窗打开时不会触发）
- 每个事件可以有多条参考链接（可带标题），详情中逐条列出；编辑页可添加、修改、删除
- **调试模式**：侧栏底部的“调试模式”开关（只在本地 `npm start` 启动时显示，见下文），默认关闭，状态保存在当前浏览器中。开启后在顶栏下方显示网站最近更新时间和版本，右上角最左侧显示 GitHub 仓库按钮和“清除缓存并刷新”按钮（绕过浏览器缓存重新下载网页、代码、样式和数据后刷新，保存在浏览器中的修改和设置不受影响），并显示全部编辑功能（新增、编辑、删除、恢复默认数据）；关闭时这些编辑功能全部隐藏，其余功能不变
- 数据保存在 `data/<国家>_<语言>.json`：本地运行时修改直接写入该文件，线上浏览时修改保存在访问者自己的浏览器中（见下文）
- **反馈 / 建议修改**（所有访问者，不需要调试模式）：事件详情底部的“反馈 / 建议修改”按钮自动带上该事件，可选反馈类型（事实错误、错别字、图片有问题、链接失效、其他；图片问题可指出第几张图并建议图片网址），也可以“直接建议修改内容”——打开编辑页的建议模式，预填标题、时间、简要说明、详细说明、类型、参考链接，提交时只发送改动的字段及改前改后、一句说明和可选的联系方式（不修改网站数据，不开放图片上传）。侧栏底部的“反馈 / 建议新增事件”用于整站反馈和建议新增事件。反馈通过 [Web3Forms](https://web3forms.com) 发送到维护者邮箱，见下文“反馈设置”

## 反馈设置

反馈通过 Web3Forms 发送到维护者邮箱（免费额度每月 250 条）：

1. 在 https://web3forms.com 输入接收反馈的邮箱，获取 Access Key（会发到该邮箱）；
2. 把 Access Key 填入 `js/config.js` 的 `feedback.accessKey`，提交并部署（已配置）。

Access Key 设计上就是公开写在网页中的（只能用来向该邮箱发送表单）。`accessKey` 为空时反馈入口照常显示，提交时提示“反馈服务尚未配置”；`enabled: false` 时不显示任何反馈入口。表单带有防垃圾的隐藏字段（`botcheck`）。

## 数据来源

事件文字由本站编写，参考了维基百科等资料（每个事件的参考链接列在详情中）。图片全部来自[维基共享资源](https://commons.wikimedia.org/)，
只收录公有领域或知识共享（CC）许可的图片，每张图片都记录了作者、许可证和原图地址，并在图片查看器、详情页“图片来源”和事件静态页中署名。
图片全部保存在 `images/` 目录，网站只从本地加载图片，版权及许可以各文件在维基共享资源上的说明为准。

背景音乐为拉格《蒂朗加》（Raga Tilanga），拉维·香卡（Ravi Shankar）等1937年录音，公有领域，来自维基共享资源（File:Raga_Tilanga.ogg），转为单声道 56 kbps 的 MP3。

标题字体为[思源宋体粗体（Noto Serif SC）](https://fonts.google.com/noto/specimen/Noto+Serif+SC)（SIL Open Font License 1.1），
只保留标题和时期名用到的字（`css/fonts/noto-serif-sc-title.woff2`，约 20KB），许可证见 `css/fonts/OFL-NotoSerifSC.txt`。
新增的时期名若含子集外的字，会自动回退为宋体显示。
英文界面的标题字体为 [Cinzel](https://fonts.google.com/specimen/Cinzel)，正文为 [EB Garamond](https://fonts.google.com/specimen/EB+Garamond)
（均为 SIL Open Font License 1.1，拉丁字符子集，由框架 history-common 提供）。

英文数据集 `data/in_en.json` 是 `in_zh.json` 的翻译（事件 id、年份、图片与中文版一一对应，参考链接按语言列出对应的维基百科条目）。

## 本地运行与编辑数据

纯静态网站，无需构建。网页、服务器和工具都在框架 [history-common](https://github.com/plantatree2023/history-common) 中（`package.json` 的依赖），先安装依赖，再在项目目录运行：

```bash
npm install             # 首次，或框架版本更新后
npm start               # 启动本地服务 http://127.0.0.1:4173/（提供调试模式）
npm run start:public    # 同上，但不提供调试模式，看到的与线上一致（等同于 npm start -- --no-debug）
```

编辑功能只在**调试模式**下显示：打开“浏览所有历史事件”侧栏，打开底部的“调试模式”开关。
**“调试模式”开关只在本地启动时显示**：线上和 `--no-debug` 时不显示，浏览器中保存的开启状态也不起作用。
例外：网址带 `debugMode` 参数（如 `…/?debugMode`）时线上也显示开关（线上的修改只保存在当前浏览器中）；浏览过程中网址保留该参数，分享链接不带。
原理：仓库中的 `js/env.js`（部署到线上的版本）为 `debugAvailable: false`，本地服务器默认改为返回 `true`。

**本地文件模式**：通过 `npm start` 访问时，在网页中新增、编辑、删除事件会直接写入 `data/in_zh.json`，
上传的图片保存到 `images/`（以内容哈希命名）。确认无误后提交并推送，线上网站就会更新：

```bash
git add data images && git commit -m "更新历史事件" && git push
```

**编辑页添加图片**：可以上传图片，也可以粘贴图片网址。网址对应的图片会先下载到本地再加入，数据中不保存外部网址：
本地文件模式下由本地服务器下载并保存到 `images/`；浏览器模式下由浏览器下载（需要对方网站允许跨域下载，
例如维基共享资源），压缩后与上传的图片一样保存在当前浏览器中；不允许的网站会提示先保存到电脑再上传。

**浏览器模式**：在 Cloudflare、GitHub Pages 等静态托管上没有写入接口，访问者的修改只保存在其浏览器的 localStorage 中（只保存改动过的字段和删除的事件，数据文件以后的更新对没有改动过的内容仍然生效），
不会影响仓库数据；侧栏底部可“恢复默认数据”。

**网站更新时间**：调试模式下顶栏下方显示“网站最近更新”的时间（按浏览器所在时区）和版本号，来自网站根目录的 `version.json`。
该文件由构建脚本 `tools/build-site.js` 在每次部署时生成（Cloudflare 在每次 push 到 `main` 时运行构建命令 `node tools/build-site.js`），记录部署时间、提交哈希和提交时间，不需要手工维护，也不提交到仓库；
部署到 Cloudflare 时用同一个脚本（构建命令 `node tools/build-site.js`，部署命令 `npx wrangler deploy` 按 `wrangler.jsonc` 只上传 `_site`）；
本地运行时由 `server.js` 根据 git 最近一次提交生成（显示“本地”）。

**社交分享卡片**：`index.html` 中有全站的 `og:` / `twitter:` 元数据（标题、简介、封面图），在微信、微博、Telegram、X 中分享链接会显示卡片；
封面图 `images/share/cover.png`（1200×630）和主屏幕图标 `images/share/apple-touch-icon.png`（180×180）由 `node tools/share-images.js` 生成（标题字体、纹理和时期配色取自网站）。
`og:url`、`og:image` 必须是绝对地址，目前写的是 https://india.zhongshutime.com/ （与 `package.json` 的 `homepage` 一致，`tests/share-card.spec.js` 检查），换域名时两处一起改。

## 从维基百科导入事件

`tools/wiki-import.js` 按关键词查询维基百科，新增或更新数据集中的条目：

```bash
npm run wiki -- --file data/in_zh.json 淝水之战 北京奥运会      # 一个或多个关键词
npm run wiki -- --file data/in_zh.json --list topics.txt         # 条目表，逐条查询
npm run wiki -- --file data/in_zh.json --dry-run 北京奥运会      # 只显示将做的修改，不写文件
npm run wiki -- --file data/in_zh.json --year 1997 香港回归      # 指定年份
npm run wiki -- --file data/in_zh.json --refresh-images 淝水之战     # 用维基图片整组替换已有图片
npm run wiki -- --file data/in_zh.json --type 战争 --score 6 淝水之战  # 指定类型和重要程度
npm run wiki -- --file data/in_zh.json --credits                    # 补全所有事件图片缺少的版权信息
npm run wiki -- --file data/in_zh.json --credits --dry-run 淝水之战  # 只补全这些事件（按事件名），只显示不写入
```

- 条目表每行一个关键词，可写成 `关键词|年份|类型|重要程度`，后几项可省略或留空（公元前写负数；例如 `淝水之战|383|战争|6`、`淝水之战|||6`），`#` 开头为注释。
- 维基语言由文件名决定（`in_zh.json` → 中文维基，简体）。关键词先按条目名查询，查不到再搜索；
  搜索到的条目须在简介中提到该关键词，否则视为找不到。
- **图片一律下载到本地**：维基图片（维基生成的缩略图，通常几十 KB）下载到数据文件上一级目录的 `images/`
  （`data/in_zh.json` → `images/`），按内容哈希命名、同一张图只存一份，并记录宽高和维基上的作者、许可证、文件页网址；单张下载失败时跳过并提示。
- **补全版权（`--credits`）**：不导入内容，只为已有图片补上缺少的 `author` / `license` / `sourceUrl`。在事件的维基条目（参考链接中的维基百科链接和 `wiki` 字段，找不到时再看该条目的中文 / 英文版本）中找与本地图片**完全相同**的文件
  （长宽比相同，下载维基缩略图后内容哈希相同，或像素比对几乎一样），已有的字段不覆盖，找不到时不填写；同一国家其他语言的数据集（如 `in_en.json`）中相同的图片一起补全，改动的事件更新 `updatedAt`。
- **已存在的条目**（事件名与关键词相同，或对应同一维基条目）：更新详细说明等来自维基的内容；参考链接中同一维基站点的链接更新为当前条目地址（没有时加在最前面），其他链接保持不变；
  保留事件名、年份、简要说明、类型、重要程度等人工内容；指定了年份、类型或重要程度时以指定的为准。已有图片默认保留
  （没有图片的条目会从维基补上），加 `--refresh-images` 则用维基图片整组替换。
- **新条目**：事件名使用关键词；年份取自 Wikidata，取不到时从简介文字中查找（会提示核对），
  仍无法确定则报错，需要用 `关键词|年份` 或 `--year` 指定。
- **类型与重要程度**：新条目自动填写，已有条目缺少时补上（都会提示核对）。
  类型依次取自 Wikidata 的“性质”（如战役→战争、条约→对外交流、考古学文化→史前）、事件名中的关键词（如“之战”“条约”“发明”）、
  年代（前 2000 年以前为史前）、简介首句中的关键词；都无法判断时不填写并提示。用现有 100 个事件检验，仅凭关键词即有 94 个与人工分类一致。
  重要程度根据 Wikidata 中该条目的语言版本数估算（越多越受关注，范围 2–9），没有 Wikidata 时为 5。
  这只是粗略的参考：与人工评分相比约 57% 相差不超过 1，建议导入后核对，或用 `--score` / 条目表第四项直接指定。
- `--dry-run` 只显示将做的修改和将下载的图片数量，不下载、不写文件。
- 写入前按网站服务器的同一套规则校验数据；遇到维基限流会自动等待重试。

## 数据格式与多语言

每个数据集是一个 JSON 文件，命名为 `data/<国家>_<语言>.json`（如 `in_zh.json`、`jp_ja.json`），包含时期划分 `eras`
和事件 `events`；通过网址参数切换：`?data=jp_ja`，默认 `in_zh`。所有字段的含义与规则见 [`data/README.md`](data/README.md)。

**界面语言**由数据集名称中的语言决定（`in_zh` → 中文，`in_en` → 英文，`?data=in_en` 打开英文版）。界面文字以中文为原文写在
`index.html` 和 `js/app.js` 中（脚本中的文字写成 `_('中文原文', { 名称: 值 })`），各语言的译文、网站名称、字体以外的设置
（年份格式、编辑页的长度上限）在 `js/i18n/<语言>.js` 中，按中文原文给出译文；字体在 `css/style.css` 的 `:root:lang(en)` 中设置。
右上角的语言下拉菜单（手机在“⋯”菜单中）可以切换到同一国家的其他语言，所有访问者可用。新增语言：
加 `js/i18n/<语言>.js` 并在 `index.html` 中引用，再加对应的数据集；`tests/i18n.spec.js` 检查每条原文都有译文。
事件静态页和 404 页面的文字分别在 `tools/build-site.js` 的 `PAGE_STRINGS` 和 `404.html` 的 `STRINGS` 中。

## 测试

使用 [Playwright](https://playwright.dev/) 在 Chromium 中做端到端测试，全程离线。测试大部分在框架 history-common 中（`tests/`，按本网站的 `site.config.json` 和 `data/` 检查），
本网站自己的测试在 `tests/` 中，`npm test` 一起运行。每次改动后运行：

```bash
npm install                      # 首次运行需要
npx playwright install chromium  # 首次运行需要（已安装浏览器可跳过）
npm test                         # 自动启动本地服务并运行全部测试
npm run test:report              # 查看上次的 HTML 报告（失败时含截图与操作记录）
```

各测试文件覆盖的内容见 history-common 的 README。

## 目录结构

网页（`index.html`、`css/style.css`、`js/`）、本地服务器、构建脚本、导入脚本和大部分测试都在框架 history-common 中，本仓库只放网站自己的内容：

- `site.config.json` 网站配置：网站名、默认数据集、对时期的叫法、关于本站的文字、标题字体、配色（字段说明见 history-common 的 README）
- `data/<国家>_<语言>.json` 数据集（事件与时期划分），字段说明见 `data/README.md`
- `images/` 事件图片（网站只从这里加载图片）；`images/share/` 是社交分享封面图和主屏幕图标
- `audio/` 背景音乐（各数据集在 `music` 字段中引用）
- `textures/` 背景纹理（各数据集在 `texture` 字段中引用）
- `css/fonts/` 标题字体（只含标题和时期名用到的字）及其许可证
- `tools/build-site.js` 构建入口（Cloudflare 的构建命令 `node tools/build-site.js`），调用框架的构建脚本生成 `_site/`
- `tools/share-images.js` 生成社交分享封面图和 apple-touch-icon
- `_headers` Cloudflare 的缓存规则：`images/` 下按内容哈希命名的图片缓存一年，其他文件每次验证
- `wrangler.jsonc` Cloudflare 部署配置（只上传 `_site`）
- `playwright.config.js` 测试配置（框架提供）
- `tests/` 本网站自己的测试：`tests/dataset-in_zh.spec.js`（默认数据集）
